V380 Web Camera

Self-hosted web UI for a V380 IP camera: live MJPEG, PTZ / light / IR / flip controls, and token auth. Camera credentials stay on your server; browsers only use ACCESS_TOKEN.

⚠ This is NOT the live camera

GitHub Pages hosts static documentation only. There is no live stream here. The interactive UI requires Node.js plus (for a real camera) V380Decoder on a host you control, typically at http://YOUR-HOST:3000.

Setup

  1. Clone the repo
    git clone https://github.com/LeeMcQ/v380-web-camera.git
cd v380-web-camera
  2. Copy the env template
    cp .env.example .env
  3. Edit secrets set a strong ACCESS_TOKEN. For a real camera, set CAMERA_PASSWORD, DEVICE_ID, and related fields. Never commit .env.
  4. Install and start the gateway
    npm install && npm start
    Then open http://YOUR-HOST:3000 (default port 3000).
  5. Real camera: run V380Decoder, set MOCK_CAMERA=0 and DECODER_URL (e.g. http://127.0.0.1:8080). With Docker Compose profile real:
    MOCK_CAMERA=0 CAMERA_PASSWORD=... docker compose --profile real up --build

Behaviour notes

  • 120s stream timeout — MJPEG sessions hard-stop after STREAM_TIMEOUT_SEC (default 120); the UI reconnects.
  • Token auth — Bearer header, ?token=, or access_token cookie. Unauthenticated stream/control returns 401.
  • Mock mode — MOCK_CAMERA=1 serves a generated test-pattern MJPEG (no camera / decoder).
  • Docker mock example
    MOCK_CAMERA=1 ACCESS_TOKEN=change-me docker compose up --build

Security

  • Never commit .env or real passwords / tokens (they are gitignored).
  • Prefer cookie or Bearer over durable query-string tokens when possible.
  • Expose the gateway only on a trusted network or behind HTTPS / reverse proxy.
  • Use a strong unique ACCESS_TOKEN; rotate if leaked.
